# Awarely Security Architecture Review & Hardening Audit

## Executive Summary

This document presents a comprehensive security audit and hardening assessment of the **Awarely** platform. Awarely is a privacy-first community safety awareness platform designed to assist tourists, solo travelers, and local commuters.

> [!WARNING]
> **Prototype Status Disclaimer:** This application is currently an advanced web prototype. **No claim is made that the application is unconditionally or perfectly secure.** This audit outlines the defense-in-depth protections implemented, as well as known residual risks and operational requirements for commercial production deployment.

---

## 1. Authentication & Authorization (RBAC)

### 1.1 Identity Provider
- **Firebase Authentication** provides the core identity layer, supporting Email/Password, Federated Google Sign-In, and Anonymous guest sessions.
- Session persistence is configured via `browserLocalPersistence`.
- Tokens are verified cryptographically via Firebase Auth JWTs.

### 1.2 Role-Based Access Control (RBAC)
Awarely strictly isolates users across three roles:

| Role | Scope | Privileges |
| :--- | :--- | :--- |
| `user` | Consumer / Traveler | View public area safety scores, submit community reports (pending moderation), manage trusted contacts, trigger check-ins / distress alerts. |
| `dev` | Engineering | All `user` capabilities + Zone Simulator (`/dev`), model inspection, and synthetic testing. |
| `admin` | Governance | All `dev` capabilities + Admin Moderation Console (`/admin`), approving/rejecting reports, viewing immutable audit trails, and deleting content. |

### 1.3 Privilege Escalation Prevention
- **Self-Promotion Guard:** In [`firestore.rules`](file:///c:/Users/Admin/.gemini/antigravity-ide/scratch/awarely/firestore.rules), the `update` rule on `users/{uid}` explicitly forbids clients from mutating the `role` attribute:
  ```javascript
  allow update: if isOwner(uid) &&
    (!request.resource.data.diff(resource.data).affectedKeys().hasAny(['role']) || isAdmin());
  ```
- **Route Guards:** Frontend routing enforces access via [`ProtectedRoute`](file:///c:/Users/Admin/.gemini/antigravity-ide/scratch/awarely/src/components/auth/ProtectedRoute.tsx) (`allowedRoles={['admin']}` and `allowedRoles={['dev', 'admin']}`) backed by component-level gatekeeping in [`RestrictedAccess`](file:///c:/Users/Admin/.gemini/antigravity-ide/scratch/awarely/src/components/auth/RestrictedAccess.tsx).

## 2. Firestore Security Rules Hardening

The database schema is enforced via declarative, non-bypassable server-side rules in [`firestore.rules`](file:///c:/Users/Admin/.gemini/antigravity-ide/scratch/awarely/firestore.rules):

### 2.1 The 9 Security Rule Guarantees

1. **Self-Access Only for Profiles (`users/{uid}`):**
   - Users can only read and modify their own document (`isOwner(uid)`). Admins can read all profiles for audit purposes.
2. **Anti-Tampering on Profile Roles:**
   - Client creation requires `role == 'user'` unless an admin token is present.
3. **Computed Score Write-Protection (`areas/{areaId}`):**
   - Direct client mutation of `overallScore`, `timeScores`, `confidence`, `reportCount`, and `awarenessLevel` is **strictly blocked** (`allow create, update, delete: if isAdmin()`). These values are computed exclusively server-side via the mathematical scoring engine.
4. **AI Summary Write-Protection (`areaSummaries/{areaId}`):**
   - Summaries generated by the Gemini engine are read-only for consumers and written only by admin / server credentials.
5. **Admin-Only Audit Records (`adminAuditLogs/{logId}`):**
   - Ordinary consumers and developers have zero read or write access (`allow read, write: if isAdmin()`).
6. **Developer Tools Isolation:**
   - Dev tools trigger mock state through client memory and admin-verified simulation paths.
7. **Trusted Contacts Privacy (`users/{uid}/trustedContacts/{contactId}`):**
   - Strictly user-scoped (`allow read, write: if isOwner(uid)`). No external user can discover another user's emergency contacts.
8. **Safety Events Protection (`safetyEvents/{eventId}`):**
   - Read access is restricted to the event creator or admin (`resource.data.uid == request.auth.uid || isAdmin()`).
   - Creation requires `request.resource.data.uid == request.auth.uid`.
9. **Report Moderation & Integrity Model (`reports/{reportId}`):**
   - Authenticated users can create reports only under rigid constraints:
     - Rating must be integer $1 \le r \le 5$.
     - `moderationStatus` must be `'pending'`.
     - `weight` must be `1.0`.
     - `note` length $\le 280$ characters.
     - Maximum 10 tags.
     - Forbidden from injecting fake score keys (`overallScore`, `confidence`, `isVerified`).
   - Deletion or modification is restricted to admins.

### 2.2 Explicit Deny on Tracking Collections
Continuous location tracking collections are permanently denied:
```javascript
match /routes/{document=**} { allow read, write: if false; }
match /locationHistory/{document=**} { allow read, write: if false; }
match /gpsTrails/{document=**} { allow read, write: if false; }
match /userLocations/{document=**} { allow read, write: if false; }
```

## 3. Firebase Storage Rules Hardening

The file storage layer is hardened in [`storage.rules`](file:///c:/Users/Admin/.gemini/antigravity-ide/scratch/awarely/storage.rules):

1. **Path-Scoped Authorization:** Uploads are restricted to `reportPhotos/{uid}/{filename}` where `request.auth.uid == uid`.
2. **File Size Limit:** Capped at **5 MB** (`request.resource.size < 5 * 1024 * 1024`).
3. **MIME Type Whitelist:** Restricted to standard bitmap images: `image/(jpeg|jpg|png|webp)`.
4. **Stored XSS Elimination:** Explicitly rejects SVG (`image/svg+xml`) and HTML files to eliminate script execution inside images.
5. **Immutable Uploads:** In-place file overwrites are forbidden (`allow update: if false`).
6. **Default Deny:** All unmapped paths are closed.

## 4. Secret Management & Environment Variables

### 4.1 Zero Frontend Secrets Exposure
An audit of all `import.meta.env` and `process.env` references confirms that **no sensitive server credentials are bundled into client-side JavaScript**:

- **Gemini API Key (`GEMINI_API_KEY`):** Strictly server-side only. Used in Cloud Functions / Google Cloud Secret Manager. It never appears with a `VITE_` prefix and is absent from client output.
- **SendGrid / Email Credentials (`SENDGRID_API_KEY`):** Strictly handled server-side via Cloud Functions.
- **Client Variables (`VITE_*`):** Contain only non-secret identifiers required for client initialization:
  - `VITE_FIREBASE_API_KEY`: Restricted public Firebase browser key.
  - `VITE_FIREBASE_PROJECT_ID`: Public project identifier.
  - `VITE_GOOGLE_MAPS_API_KEY`: Client-side Maps JavaScript API key.

### 4.2 Google Maps API Key Restrictions
To prevent unauthorized quota usage or bill shock, the client-facing Google Maps API key must be configured in Google Cloud Console with:
1. **Application Restrictions:** HTTP Referrers restricted to authorized domain names:
   - Development: `http://localhost:5173/*`, `http://127.0.0.1:5173/*`
   - Production: `https://awarely.org/*`, `https://*.web.app/*`, `https://*.firebaseapp.com/*`
2. **API Restrictions:** Key restricted exclusively to:
   - Maps JavaScript API
   - Places API (New)
   - Geocoding API
3. **Daily Quotas:** Hard billing alert thresholds configured at $10/day and $50/day.

## 5. Vulnerability & Injection Analysis

### 5.1 Cross-Site Scripting (XSS)
- **Zero `dangerouslySetInnerHTML`:** Automated repository grep confirms 0 instances of unescaped inner HTML injection.
- **Automatic JSX Escaping:** All user-generated text (contributor notes, observation tags, custom remarks) is safely escaped as string text nodes by React 19.
- **Zero `eval()` or Dynamic Function Construction:** No dynamic code evaluation exists.

### 5.2 Injection Risks (NoSQL / SQL)
- Firestore queries use parameterized SDK calls (`where('areaId', '==', areaId)`). SQL injection and string concatenation attacks are impossible.

### 5.3 User-Generated Content & Anti-Abuse
- **Input Character Limits:** Notes capped at 280 characters; tags capped at 10 items.
- **Anti-Spam Cooldowns:**
  - Manual "I feel unsafe" trigger: 60-second cooldown between consecutive broadcasts.
  - High-concern area entry: 1-hour cooldown per area.
  - Location awareness alerts: 60-minute default cooldown per area.
- **Rate-Limiting on Submissions:** Burst protection in feedback service prevents automated rapid-fire report flooding.

## 6. Residual Risks & Prototype Limitations

1. **Client-Side Environment Limitations:**
   - Web browser geolocation can be spoofed by a determined technical user via Developer Tools sensor simulation. For commercial operations, background OS geofencing via Flutter / native Android & iOS will provide cryptographically signed network-assisted cell/GPS geofencing.
2. **Prototype Demo Storage:**
   - In local development mode without Firebase Cloud connection, fallback demo reports and audit records are saved in `localStorage`. In production, these fallbacks are disabled.
3. **Email Delivery Simulation:**
   - In offline/demo environments, notifications record simulated audit entries. In live cloud production, a deployed Firebase Cloud Function with verified SendGrid/Resend domain authentication is required.
4. **AI Output Hallucination Risk:**
   - While the AI Safety Engine enforces rigid negative guardrails and verifies output against source tags, LLM outputs must always be accompanied by the standard prototype disclaimer and community data fresh labels.
